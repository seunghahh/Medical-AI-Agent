## 초진의무기록: 형식 통과와 작성 품질을 구분

### 제출 계약

`run.consult()`는 SOAP와 주진단을 `client.diagnose(note=..., diagnosis=...)`로 전달합니다. SDK가 `POST /v1/session/actions`에 `action=DIAGNOSE`, `request_id`, `note`, `diagnosis`를 보냅니다. 공개 서버 샘플 도구는 별도의 sample session 경로를 사용합니다.

`note`에는 S의 6칸, O의 2칸, A의 2칸, P의 5칸만 있고 모두 문자열입니다. 필드명은 README와 SDK의 RECORD_FIELDS를 참조하세요. 주진단은 note 바깥에 둡니다. 저장용 record.json의 맨 위 diagnosis를 note에 그대로 넣으면 SDK가 거부합니다. record.md/record.json 자체를 대회에 업로드하는 방식이 아닙니다. 별도로 올리는 submission.zip은 실행 코드입니다.

기존 C10(`C10-20261011-154815-354250`)를 실제 SDK의 HTTP 전송 직전까지 호출하되 네트워크는 mock 처리하고, 최신 로컬 제출 검증에도 넣었습니다.

| 점검 | 결과 |
|---|---|
| SOAP 구조 | 필수 15칸, 추가 필드 없음, 모두 문자열 |
| 예선 검사 결과 | O.tests 빈 문자열 |
| 주진단 | Graves disease, 별도 인자, 단일 행, UTF-8 14바이트 |
| 기록 크기 | 공식 로컬 렌더링 기준 UTF-8 11,106바이트, 100,000바이트 이내 |
| 요청 | DIAGNOSE 본문 구조 일치; 로컬 completed |
| 검증 범위 | 구조/크기/요청 형태만 확인. 임상적 정답·공식 서버 수락 여부는 미검증 |

### 기존 C10 기록의 남은 작성 문제

- CC에 첫 진술 전체가 들어가고 HPI·ROS·A에 같은 Q/A가 반복됩니다. 관찰 추적은 쉽지만 간결한 초진기록은 아닙니다.
- A.evidence는 근거 원문이 많고, 감별진단마다 지지·반대 이유를 해석하는 문장이 부족합니다. 실제 관찰 ID가 연결되었다는 것만으로 타당한 추론이 보장되지는 않습니다.
- 이전 기록 HPI/ROS에 검사 동의 응답이 들어갑니다. 최신 분류기는 이를 제외하도록 수정했지만 과거 결과는 재작성하지 않았습니다.
- 이전 P는 영어이며 검사별 목적과 구체적 재내원 경고가 충분한지는 별도 평가가 필요합니다. 현재 생성 지시는 한국어로 바꿨습니다.
- P.education은 앞으로의 교육 계획입니다. 실제 SAY에서 하지 않은 설명을 수행했다고 평가하면 안 됩니다.
- 약물·용량·검사·추적 계획은 모델 제안입니다. 수치/음성 표현 필터는 임상 적합성이나 안전성을 인증하지 않습니다.

따라서 **제출 구조는 맞지만, 권장 작성 방식과 임상 품질까지 완성됐다고 볼 수 없습니다.** 안전한 원문 보존을 유지하면서 간결한 요약과 감별 해석을 개선하는 작업은 별도의 변경·실제 모델 재검증이 필요합니다.

## 평가와 데이터 경계

AgentClinic/DDXPlus는 상호작용 진료 실험입니다. 정답 진단과 숨겨진 검사 결과는 Doctor 입력에서 제외합니다. ACI-Bench는 이미 주어진 대화로 기록을 만드는 과제이고, 예선 점수나 질문 선택 효율로 평가하지 않습니다. 실제 입력에 있는 검사 결과는 ACI 경로에서만 기록할 수 있습니다.

normalized_exact_match는 대소문자/기호를 정리한 진단 문자열 비교입니다. 번역·동의어·진단 수준 차이를 판정하지 못합니다. local_contract_pass는 일부 실행 조건 확인이며 공식 점수가 아닙니다. 공개 평가 영역은 6개지만 세부 문항·프롬프트는 공개되지 않았습니다.

SOAP 파일만 있으면 작성 내용만 검토할 수 있습니다. 실제 수행·환각·누락·효율을 평가하려면 시작 정보와 transcript/summary가 필요합니다. review_bundle.md는 이를 한 파일로 묶습니다. 선택적으로 넣는 공개 대본/모범기록은 평가자 전용이며 Doctor의 관찰과 분리됩니다. NOVA 개발 평가 모델은 진료 세션 밖에서만 허용되고 이 코드는 평가 API를 자동 호출하지 않습니다.

## 확인한 것과 남은 한계

- 로컬 단위/계약 테스트 30개 통과. 모델 호출은 가짜 endpoint를 사용하며 실제 모델 성능 시험이 아닙니다.
- 데이터 없는 새 checkout에서는 28개 통과, 외부 데이터 통합 2개 skip하도록 구성했습니다.
- 제출 ZIP은 실행 파일 6개 고정 목록. 데이터·로컬 환자 코드·웹 화면·원시 결과·키 제외. 독립 압축 해제 후 import/prepare/검색을 작은 합성 지침으로 확인했습니다. 원본 샘플 Markdown의 줄 끝 두 칸은 의도한 줄바꿈이므로 보존했습니다.
- GIF는 과거 실제 C10 로그 일부를 19초로 압축한 화면 재생입니다. 새 모델 실행이나 공식 점수의 증거가 아닙니다.
- RAG는 오프라인 FTS5이며 원문 인용 검증과 출처를 남깁니다. 현재 키워드 순위에 관련성이 낮은 지침이 섞입니다. 관찰 검증은 검색의 임상적 적합성을 보장하지 않습니다.
- 30분 최신 규칙 적용 후 실제 C10 재실행, Docker 2 CPU/8GB 및 네트워크 차단 환경, 공식 서버 샘플 검증은 수행하지 않았습니다. 이 머신에 Docker가 없습니다.
- 현재 공개 문서와 테스트 범위에서 확인한 불일치는 수정했습니다. 비공개 채점/서버 동작까지 포함해 규칙 위반이 전혀 없다고 단정하지 않습니다.

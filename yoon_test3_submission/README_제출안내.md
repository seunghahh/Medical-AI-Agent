# yoon_test3_submission

제출할 파일은 **submission.zip**입니다. ZIP 루트에 run.py, rag.py 등이 있습니다.
기존 yoon_test2_submission과 저장소 main 소스는 덮어쓰지 않았습니다.

## 개선 근거

사용자가 제공한 직전 결과는 총점 71.946, 정보수집 10.28/25,
진단추론 15/15, 검사·추적 5.72/10, 안전 15/15, 의사소통 5.94/15, 효율 20/20입니다.
서버 상세 대화나 세부 채점 기준은 확보하지 못했습니다. 아래 원인은 코드에서 확인한
개선 가능 지점이며, 실제 감점 원인을 확정한 분석은 아닙니다.

## 변경 사항

### 정보수집

- 초기 핵심 질문 최대 4개 뒤, 새 답변을 반영해 최대 두 차례 추가 질문 묶음을 선정합니다.
  기존 초기 4개 + 개별 추가 질문 4회에서, 최대 4개씩 세 묶음으로 바꿨습니다.
- 증상·위험 신호뿐 아니라 영양·수면·활동·카페인·노출·지지체계·약물 사용 기간,
  최근 사용·부작용 등 필요한 질문을 선택할 수 있도록 주제 범위를 넓혔습니다.
- 문진 상한 28회, 관련 진찰 상한 5회입니다. 빈 항목을 무조건 채우는 방식은 아니며,
  모델이 관찰에 근거해 필요한 질문·진찰을 골라야 합니다.
- 실제 질문과 응답만 기록하고, 미확인은 음성으로 바꾸지 않으며 중복 질문을 차단합니다.

### 검사·추적

- 검사 이름·각 검사의 목적·우선순위, 추가 확진검사의 적응증, 치료 전 안전 평가를
  명시하도록 계획 프롬프트를 보완했습니다.
- 재진 시점뿐 아니라 검사 결과·증상·측정치·부작용 중 무엇을 확인할지, 조기 재진과
  응급 진료 조건, 필요한 진료과와 의뢰 시급성을 구분하도록 했습니다.
- 이미 진단 검토에 검색한 문헌을 계획 작성에도 전달합니다. 참고 문헌은 환자 사실이 아닙니다.
- 검사·처치 결정·추적·교육이 비거나 기존 안전 필터에 차단되면 해당 빈 항목만
  한 차례 복구합니다. 주진단과 이미 통과한 다른 계획은 바꾸지 않습니다.

### 의사소통

- 새 기본 경로에서는 고정된 일반 치료 설명을 사용하지 않습니다.
  실제 계획에 있는 치료·관찰 방향을 조건과 함께 쉬운 한국어로 풀이합니다.
- 한 번의 모델 호출에서 6~10개 문장으로 원인·검사와 목적·치료·생활 주의·재진·경고를
  설명하도록 요청합니다. 한 문장은 기존처럼 30자 이내입니다.
- 검사나 치료 내용은 필요하면 두 문장으로 나눕니다. 근거가 부족하거나 형식이 틀린
  항목은 한 번 보완하고, 출력 전체가 무효이면 기존 설명기로 복구합니다.
- 재진 숫자·단위는 원래 추적 계획에서 그대로 렌더링합니다. 설명에 임의의 숫자나
  약 용량을 넣거나 즉시 약을 바꾸도록 안내하는 출력을 차단합니다.
- 발언 턴이 부족하면 원인·검사·경고·재진을 우선 확보합니다.
  이해도·걱정 확인과 실제 응답 기록도 유지합니다.

## 보존한 기능

- v2의 주진단 생성·검토 프롬프트와 약물 안전 처리 함수가 동일함을 AST로 확인했습니다.
- rag.py, grounding.py, nova_sdk.py, requirements.txt는 v2와 바이트 단위로 같습니다.
- 관찰 원문 기반 S/O/A, 예선 O.tests 공백, 요청 ID 재시도 방식과 50턴 제한을 유지합니다.
- 샘플 대본·정답·증례 ID를 실행 분기로 사용하지 않으며 제출 ZIP에 넣지 않습니다.

## 검증

- 회귀·추가 테스트 76개: 74개 통과, 외부 데이터 파일이 없는 2개 건너뜀.
- 남은 턴 1~50개에서 최종 제출·문장 길이·턴 상한 확인.
- 새 답변을 받은 후 질문을 다시 고르는지, 피드백이 S/O/A에 섞이지 않는지 확인.
- 구체적인 검사·치료 설명과 재진 단위 보존, 위험/재진 안내 우선 배정,
  용량 및 즉시 약물 변경 안내 차단, 빈 계획만 복구하는 동작 확인.
- 이전 종료 대화 개수 고정 테스트 2개는 새 경계/예산 검증으로 대체했습니다.
  기존 설명기 전용 테스트 3개는 비상 복구용 설명기에 적용하고 새 설명기는 별도로 검증했습니다.
- ZIP을 독립 압축 해제하여 import, prepare, 합성 문서의 실제 FTS5 검색을 확인했습니다.

테스트 모델은 가짜 응답입니다. 실제 Doctor 모델·전체 지침 색인 성능·서버 평가를
실행하지 않았으며 점수 상승이나 기존 만점 유지를 보장하지 않습니다. 추가 문진·진찰·
설명은 턴과 토큰을 늘릴 수 있습니다. 출력 품질에 따라 설명 재작성·빈 계획 복구 호출도
발생하므로 실제 효율은 동일 조건의 서버 재평가로 비교해야 합니다.

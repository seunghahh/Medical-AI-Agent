# yoon_test4_submission

업로드 파일은 **submission.zip**입니다. ZIP 루트에 run.py, rag.py 등이 있습니다.
기존 main 및 yoon_test2/3_submission은 보존했습니다.

## 목표와 기준

사용자 제공 직전 결과: 총점 73.301, 정보수집 10.73/25, 진단추론 13.33/15,
검사·추적 7.50/10, 안전 15/15, 의사소통 6.78/15, 효율 19.96/20.
실제 감점 근거/서버 대화는 확인하지 못했으므로 아래는 코드에서 확인한 문제에 대한 개선입니다.

## 정보수집

- 이미 관찰된 기본 병력은 모델이 원문 전체와 출처 ID를 제시하고 코드가 일치를 확인한
  경우에만 재질문을 생략합니다. 음성도 명시적으로 확인한 것만 허용합니다.
- 과거력·약물·알레르기·가족력·흡연·음주만 생략 대상입니다. 미확인/부분 답변은 생략하지
  않도록 지시하며, 출처의 주제도 검사합니다. 약물 답변으로 알레르기 문진을 생략하지 않습니다.
- 이 검사는 출처 존재와 주제를 검증합니다. 답변의 임상적 충분성 판단은 모델에 의존하며,
  출처 일치만으로 모든 의미상의 오류가 배제되지는 않습니다.
- 양성 증상의 빈도·강도·지속시간, 감별에 필요한 음성 증상, 양성 흡연·음주 노출량,
  이전 검사 및 환자 목표를 확인하도록 질문 우선순위와 선택 가능한 주제를 보강했습니다.
- 가족력 질문을 '비슷한 증상'에 한정하지 않도록 바꿨습니다.
- 기존 3차례 관찰 기반 질문 묶음, 관련 진찰 최대 5개, 문진/설명 예산을 유지합니다.

## 의사소통

- 기존 질문 판정은 '오세요', '중단하지 마세요' 같은 안내까지 질문으로 오인할 수 있었습니다.
  새 설명 전용 판정기로 실제 질문과 공손한 안내를 구분합니다. 환자 사실 분류기는 그대로입니다.
- 첫 원인 설명에는 불확실성을 유지하되, 두 번째 기전 설명에 같은 표현을 강제하지 않습니다.
  실제로 말한 걱정을 전달해 환자 중심의 설명을 생성하도록 했습니다.
- 구체적인 검사/목적, 조건부 치료, 재진, 위험 증상, 생활 주의를 최대 8문장으로 전달합니다.
  각 문장은 30자 이내이며 위험/재진 안내를 우선 남깁니다.
- 즉시 약물 변경 지시는 계속 차단하면서, '약을 임의로 중단하지 마세요' 같은 보호적 안내는
  허용합니다. 임의 용량·새 숫자·확정 진단 표현은 기존과 같이 제한합니다.

## 효율

- '네, 이해했어요. 감사합니다' 같은 단순 확인 응답에는 추가 모델 호출을 하지 않습니다.
  '네, 그런데 약은 언제 바꾸나요?'처럼 실질적인 질문이 뒤따르면 응답을 생성합니다.
- 설명 생성에 실패해도 예전의 항목별 모델 호출로 연쇄 재시도하지 않습니다. 묶음 요청은
  최대 2회이며, 그 뒤에는 출처가 있는 경우 일반적인 불확실성/상담 안내만 보완합니다.
- 설명 프롬프트에는 긴 전체 HPI 대신 실제로 받은 걱정 응답을 전달합니다.
  문진 프롬프트에서도 같은 관찰의 raw/value 중복 전송을 제거했습니다.
- 실제 서버 효율 점수와 토큰 비용의 감소를 보장하지 않습니다. 전체 계획/진단 호출과
  SDK의 일시 오류 재시도는 기존 정책을 유지합니다.

## 검증

- 회귀·추가 테스트 82개: **80개 통과, 외부 데이터 미설치 2개 건너뜀**, 종료 코드 0.
- 남은 턴 1~50에서 최종 제출·턴/문장 길이 한도 확인.
- 진단 생성/검토 프롬프트 및 약물 안전 함수가 기존과 같음을 AST로 검사했습니다.
  rag.py, grounding.py, nova_sdk.py, requirements.txt도 바이트 단위로 같습니다.
- 예선 O.tests 공백, 원문 기반 기록, 문진 중복 차단, 빈 검사·추적 계획 복구,
  재진 단위와 위험 안내 보존, 피드백의 S/O/A 유입 차단 등을 점검했습니다.
- 같은 가짜 환자 응답의 통제된 비교: v3 모델 호출 9회/행동 17턴 → v4 7회/15턴.
  이는 단순 확인 응답에서 불필요한 2회 호출·2턴이 사라지는 검증이며 실제 증례 평균이나
  임상 품질·공식 효율 점수의 측정이 아닙니다. efficiency_comparison.json을 참고하세요.
- ZIP 독립 압축 해제 후 import, prepare, 합성 문서의 실제 FTS5 검색을 확인했습니다.
- 기존 종료 개수 고정 테스트 2개는 새 경계/턴 테스트로 대체하고, 기존 설명기 테스트 3개는
  해당 레거시 함수에 적용했습니다. Windows 모니터 테스트에서만 POSIX용 os.kill(pid, 0)
  확인을 가짜 응답으로 대체했습니다. 모니터는 제출 ZIP에 포함되지 않습니다.

실제 Doctor 모델·서버 재평가·전체 지침 색인 성능은 이번에 실행하지 않았습니다.
정보수집/의사소통 상승, 다른 항목의 점수 유지 및 효율 만점은 서버에서 확인해야 합니다.
제출/유료 평가 호출은 자동으로 실행하지 않았습니다.

기존에 확인한 공식 형식/기준: https://nova.snubhai.org/docs/ 및 https://nova.snubhai.org/evaluation/

## 개선 내용

- 초기 공감·걱정 확인 후 증상에 맞는 질문 최대 4개를 한 번의 모델 호출로 선정합니다.
  이미 물은 질문, 중복 주제, 기본 병력 대기열과 겹치는 주제, 30자 초과 출력을 차단합니다.
- 시작·경과, 위치·양상·정도, 악화·완화 요인, 관련 위험 신호, 동반 증상과 생활 영향을
  우선하도록 지시했습니다. 직업·노출력 등 필요한 추가 문진 주제도 확장했습니다.
- 초기 묶음 질문 뒤 기존 기본 병력과 최대 4회의 적응형 문진을 진행합니다.
  문진 상한은 24회, 진찰은 최대 3개이며 설명·피드백을 위한 턴과 시간을 남깁니다.
- 기존 원인·검사·치료방향·추적·위험증상 설명 뒤 이해도 확인과 추가 걱정 질문을 합니다.
  환자가 실질적인 답변을 하면 기존 계획 안에서 짧게 응답하며, 단순 동의·자료 없음에는
  추가 모델 호출을 생략합니다. 새 질문이나 처방으로 계획을 변경하지 않도록 지시합니다.
- 실제 설명·질문·환자 반응만 P.education에 기록합니다. 이해도 확인 답변은 S/O/A에 넣지 않습니다.

## 보존한 기능과 RAG

- 원래의 진단·감별·계획 생성 프롬프트와 약물 안전 처리, 관찰 원문 기반 S/O 및 근거 작성,
  예선 O.tests 공백, 재시도 요청 ID 방식과 30자 제한을 보존했습니다.
- rag.py, grounding.py, nova_sdk.py, requirements.txt는 main 사본과 동일합니다.
- 요청하신 RAG 파일은 실제 import와 Linux 대소문자 규칙에 맞춰 **rag.py** 이름으로 포함했습니다.
  파일을 RAG.py로만 바꾸면 서버에서 import가 실패할 수 있습니다.
- 서버의 NOVA_GUIDELINES_DIR 자료를 SQLite FTS5/BM25로 검색합니다. 문헌은 환자 사실로 쓰지 않으며,
  문헌 데이터나 외부 모델을 ZIP에 넣거나 실행 중 내려받지 않습니다.

## 검증과 한계

- 오프라인 회귀·추가 테스트 69개: 67개 통과, 외부 데이터 파일 미설치로 2개 건너뜀.
- 피드백 추가로 바뀐 기존 종료 대화 개수 기대값 2개는 새 경계·턴 예산 테스트로 대체했습니다.
  기존 가상 모델에는 새 피드백 단계 응답만 추가했습니다.
- 남은 턴 1~50개 전 범위에서 최종 제출 완료와 턴·문장 길이 제한을 확인했습니다.
- 환자 피드백 API 실패 시에도 최종 기록 제출, 피드백의 S/O/A 유입 차단,
  중복 질문 차단, 숫자·용량을 포함한 피드백 응답 차단 등을 확인했습니다.
- 독립 압축 해제 후 import, prepare, 합성 문서의 실제 FTS5 검색을 검증했습니다.
- 테스트 모델은 가짜 응답입니다. 실제 Doctor 모델·공식 서버 평가와 전체 지침 색인 성능은 미검증입니다.
  서버 제출·유료 API 호출은 수행하지 않았습니다.
- 안전 15점·효율 20점 유지나 점수 상승은 보장할 수 없습니다. 문진과 피드백이 늘어 실제
  턴·토큰 비용이 증가할 수 있으므로 기존 제출과 동일 조건으로 서버에서 비교해야 합니다.
